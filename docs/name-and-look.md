# The name and the look

## Why Berthline

My computer is modest, and IntelliJ IDEA, which I use for my Java studies, was too heavy for it. So
I started bringing VS Code as close as I could to the IntelliJ IDEA experience, using it as
inspiration.

The goal isn't to turn an editor into a complete IDE. It is to get close enough to work comfortably
on small and medium projects, and move to a full IDE when a project outgrows it. Java was the start;
Web came next, and more will follow. Keeping profiles apart means a Java setup never slows down a Web
project.

## The name

A *berth* is the place where a ship docks. A *line* is a shipping line, a fleet that sails under one
flag. Berthline is a fleet of coding tools, and each one has its own berth.

## The profile names

Each profile is a boat, named with the same letter as what it carries:

| Profile | Boat | Cargo |
|---|---|---|
| Bean Barge | barge | coffee beans, for Java |
| Web Wherry | wherry | the Web |
| Standard Sloop | sloop | the plain editor |

Reserved for later profiles: C Cutter, Python Pinnace and Makebench Drydock. The internal ids stay
`java`, `web` and `standard`.

## The look

The Hub's main screen is the Cargo: one boat per profile, with its state and main action. A running
app sails, a ready one rests at anchor, and the red flag only shows when something needs you.

The icons share the same hull and change only the cargo: steam for Bean Barge, `< >` for Web Wherry
and a prompt for Standard Sloop. The Hub is the ship with the red flag. They are flat, in solid
colours, so they stay clear at small sizes.

Editors keep a quiet dark theme, run buttons where you expect them, and a choice of IntelliJ or
VS Code keys where it makes sense.
